the whole path

npu and gpu race for every step they can run. the cpu takes parallel work and logic. the main thread only draws.

every step

race means both chips get built and the faster exact one keeps the step. parallel means the cpu splits it across cores. backup runs only if the others fail the golden test.

three audio blocks, each with mel (m), encoder (e), decoder (d) and beam work (b). a column is one turn in order. it is not a timing.

the combined engine

this is the goal: all of it at once. every chip has its next job ready before the current one ends, so no chip sits idle while work remains. the number on a tile is its batch, and a column is one turn in order, not a timing.

how calls get packed

  1. keep every chip fed. the next batch is queued before the current one finishes.
  2. pack the calls. many pieces go into one gpu command buffer or one npu batch, and the next call is prepared while this one runs.
  3. fill the token gap. one stream must wait for its last token, so other pieces use the chip during that wait.
  4. never copy. chips hand off shared memory buffers.
  5. slow down, never overflow. bounded queues hold back the stage before a slow one.
  6. recover on its own. if a chip call fails or falls back, that piece reruns on the exact gpu path.

six ways to pack

the engine combines these. each one is a bet the hill-climb can keep or drop.

the decoder's ceiling

each decoder step reads its weights from memory. at the m4's 120 gb/s, that caps one stream no matter which chip runs it. these are estimates until measured.

what decides a placement

  1. it is exact. it passes the golden test on all three clips, or it is out.
  2. it wins the task's number. throughput, speed or latency.
  3. on a tie, the npu wins. a tie is within 3%.
