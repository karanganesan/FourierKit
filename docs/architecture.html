the whole path

npu and gpu race for every step they can run. the cpu takes parallel work and logic. the main thread only draws.

every step

race means both chips get built and the faster exact one keeps the step. parallel means the cpu splits it across cores. backup runs only if the others fail the golden test.

the combined engine

one wide decoder batch on the fastest chip, the encoder working ahead on the other, and the cpu running beam logic. x, y and z are audio pieces, a number is a decoder step, and each row of a piece is a beam. a column is one turn in order, not a timing.

the decoder is drawn on the gpu and the encoder on the npu as an example. the race decides which chip gets which.

how calls get packed

  1. one wide decoder batch. beams and pieces share each weight read.
  2. refill slots at once. when a piece ends, the next one takes its slot without draining the batch.
  3. encoder works ahead. the other chip prepares the next piece, so the batch never waits for audio.
  4. never move beam data. cache rows stay put, and a small index table tracks which beam owns each row.
  5. pack the calls. many pieces go into one gpu command buffer or one npu batch, and the next call is prepared while this one runs.
  6. slow down, never overflow. bounded queues hold back the stage before a slow one.
  7. recover on its own. if a chip call fails or falls back, that piece reruns on the exact gpu path.

what it reads

audio length, queue, deadlines, measured step time, memory pressure, thermal state, power, and chip health.

what it changes

what it never changes

the answer. only exact paths are eligible, at any batch width and any load.

the decoder's ceiling

the gpu on this mac measured about 91 gb/s of memory reads, below the chip's 120 gb/s spec. this is the fastest a 2-minute clip could decode from weight reads alone.

what decides a placement

  1. it is exact. it passes the golden test on all three clips, or it is out.
  2. it wins the task's number. throughput, speed or latency.
  3. on a tie, the npu wins. a tie is within 3%.

build order

  1. measure the ceiling. a one-layer test on the npu and gpu sets the real memory limit.
  2. batch the beams on one exact 32-bit path.
  3. index the beam cache, so its rows never move.
  4. prove 16-bit. if it passes the golden test, it could roughly double single-clip speed.
  5. widen the batch and refill its slots.
  6. move the encoder ahead onto the other chip.
  7. turn on the scheduler, starting from the sizes above and tuning them with measurements.
