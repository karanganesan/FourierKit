the fourierkit api

three modes, every option public, one line to start. import FourierKit, and call Fourier().

the engine, the sdk and the default ui exist. the golden test checks the engine directly and these calls for a file, a recording and live replay.

start here

one line gives the best result. every option has a default, and every default is the exact path.

import FourierKit

let speech = Fourier()
try await speech.prepare()                              // optional: every mode prepares on first use

let transcript = try await speech.transcribe(contentsOf: url)
print(transcript.text)

Fourier is a final class and is Sendable. it is safe to call from the main actor: every heavy call is async and leaves the caller's actor at once, and streams are produced off the main actor and coalesced to at most one value per frame. there is one engine per process, so every Fourier instance shares the same weights.

signaturewhat it does
init(_ options: FourierOptions = FourierOptions())the default is the recommended setup. see the options reference.

func prepare() async throwsdownloads, verifies, loads and warms the model. optional. calling it again joins the same run, and the work stops only when the last waiting caller cancels. a model that is already ready finishes at once.
var prepareProgress: AsyncStream<PrepareProgress>one smooth value from 0 to 1 for the current or next prepare run. see prepare progress.
func warm() async throwsapplies the keep-warm option, then does the same as prepare().
func cool() asynclets go of the model's memory if nothing is running. the next use warms it again.

transcribe

audio up to 120 s runs in one pass and is never split, so it matches the reference path. longer audio is cut at quiet points by one deterministic splitter, each piece runs the exact path and the pieces are joined with single spaces. if a piece reaches the token limit without a stop token, it is split and decoded again, so text is never silently cut off. file decoding and resampling to 16 khz happen inside the kit. files and recordings are never cleaned.

func transcribe(contentsOf url: URL) async throws -> Transcriptany file core audio can open
func transcribe(_ recording: Recording) async throws -> Transcriptthe result of record()
func transcribe(samples: [Float], sampleRate: Double = 16_000) async throws -> Transcriptmono samples at any rate, resampled to 16 khz if needed
func transcriptionJob(contentsOf url: URL) -> TranscriptionJobstarts the same work and returns a handle with its own progress, result and cancel
func transcriptionJob(_ recording: Recording) -> TranscriptionJobthe same, for a recording
func transcriptionJob(samples: [Float], sampleRate: Double = 16_000) -> TranscriptionJobthe same, for samples

cancelling the task that is awaiting one of the transcribe calls cancels the work. a job handle is different: cancelling a task that awaits job.result does not cancel the job. only job.cancel() does.

let samples: [Float] = []   // your own 16 khz mono audio
let text = try await speech.transcribe(samples: samples).text
let other = try await speech.transcribe(samples: samples, sampleRate: 48_000).text

the job handle

let job = speech.transcriptionJob(contentsOf: url)
let watching = Task {
    for await fraction in job.progress { print(fraction) }   // 0...1, ends with the job
}
let reading = Task {
    for await update in job.updates {                        // text while it is worked out
        print(update.settled, update.draft)                  // settled never changes, draft may
    }
}
// job.cancel() stops at the next piece boundary, and result then throws FourierError.cancelled
let transcript = try await job.result                        // the one to keep
await watching.value
await reading.value

progress moves through the whole job, also when the audio is one piece: a little for the encoder, a little for the prefill, then step by step against an estimate of how many words that much audio holds. updates carries the text so far: pieces that are finished, from the start of the audio, are settled, and what the engine has after that is draft. with beam search, the default, a draft can be rewritten before its piece ends. neither changes the transcript, which comes from result.

record

raw capture with a live level, then the same path as transcribe. recorded audio is not cleaned: no noise suppression, no echo cancellation and no gain, so it can match the reference. the first call asks for the microphone as options.permissions allows. the engine warms while you record, so the transcript can start at once. a warm-up never starts a download.

let recorder = try await speech.record()
let meter = Task {
    for await level in recorder.levels { print(level) }   // 0 (silence) to 1 (full scale)
}
let reading = Task {
    for await update in recorder.drafts {                 // draft text while recording
        print(update.settled, update.draft)
    }
}
// ... later
let recording = await recorder.stop()
await meter.value
await reading.value
let transcript = try await speech.transcribe(recording)  // one exact pass, the one to keep

while recording, quick greedy passes run over the raw audio so far and arrive on drafts. a stretch longer than 20 s is cut at a quiet point and set aside as settled, so a pass never grows with the recording. the drafts are not the transcript: that comes from transcribe on the recording and may word things differently. set options.recordDrafts = false to record without them. they need the model on the device, and recording never starts a download for them.

listen

live text while you speak. the model is not a streaming model, so live text is built on top of it: finished audio blocks are encoded once and cached, only the newest audio is encoded on each short step, and text that agrees across passes settles. a pause ends a phrase, settles all of it and resets the window, so the cost stays flat in a long session. the first call asks for the microphone and prepares the model if needed.

let live = try await speech.listen()

let reading = Task {
    for try await event in live.events {
        switch event {
        case .started:                    break   // the input is live
        case .level(let level):           print(level)                // for a meter
        case .speechStarted:              break   // voice detected
        case .update(let update):         print(update.settled, update.draft)
        case .phraseEnded(let phrase):    print(phrase.text)
        case .warning(let warning):       print(warning)
        }
    }
}

// when the user stops: stop the input, get the final text, end the stream
let transcript = try await live.finish()
try await reading.value

// or, instead of finish(): stop, discard and end the stream
// live.cancel()

promises the api makes

  • settled text never changes. it only grows.
  • draft text can change or vanish on any update. it is always the newest guess for the audio after the settled part.
  • drafts are optional. with drafts off, or when nothing is uncertain, the draft is empty and only settled text arrives.
  • settled plus draft is always the best full text so far.
  • the transcript from finish() comes from the exact passes. its wording can differ from the live text, and it is the one to save.
  • levels and updates keep only the newest. a slow reader gets the newest value, and memory stays bounded. the other events queue in order.
  • cancelling the task that reads events does not stop the session. only finish() or cancel() does.
  • if the mac falls behind, updates slow down before any audio is dropped, and a warning says so.

options for one session

var listenOptions = ListenOptions()
listenOptions.drafts = false                       // settled text only
listenOptions.pauseToEndPhrase = .milliseconds(800)
listenOptions.finalPass = .fullAudio
let live = try await speech.listen(listenOptions)

every ListenOptions field and its default is in the options reference. to try listen without a microphone, play a file in as if spoken:

var listenOptions = ListenOptions()
listenOptions.audioSource = FileAudioSource(url: url, realtime: true)
let live = try await speech.listen(listenOptions)   // no microphone, no permission prompt

the final transcript is one exact pass per phrase, started as soon as the phrase closes, so finish() only waits for the last phrase. with finalPass = .fullAudio it is one pass over everything heard, which is slower to finish.

prepare progress

one value from 0 to 1 that covers everything from download to warm-up. any number of observers can read it, and calling prepare() twice joins the same work.

let preparing = Task { try await speech.prepare() }

for await progress in speech.prepareProgress {
    print(progress.stage.name)          // "downloading"
    print(progress.fraction)            // 0.0 to 1.0, never goes backward
    print(progress.bytesDone, progress.bytesTotal)   // during download
    print(progress.timeRemaining as Any)             // nil until it can be estimated
}

try await preparing.value

state and metrics

one source of truth. an app can draw its whole interface from the state. updates are coalesced to one per frame and produced off the main actor.

let state = await speech.state                  // latest snapshot
for await state in speech.states {              // every change, newest value only
    print(state.engine, state.jobs.count, state.pressure)
}

for await metrics in speech.metrics {           // about four times a second, only while read

microphone and permissions

the microphone is asked for only when needed. the first listen() or record() requests it, never app launch, and file transcription never asks. reading state never prompts. only requestMicrophone(), listen() or record() can show the system dialog.

let mic = await speech.microphone                       // latest snapshot, never prompts
for await mic in speech.microphoneStates {              // permission, capture and device changes
    print(mic.permission, mic.capture, mic.device?.name ?? "no input")
}
for await level in speech.microphoneLevels { }          // meter, newest value

let permission = await speech.requestMicrophone()       // asks only if never asked
if permission == .denied { speech.openMicrophoneSettings() }

take over the prompt

var options = FourierOptions()
options.permissions = .manual            // the sdk never prompts. record() and listen() throw
                                         // FourierError.microphoneNotRequested until you ask.
// or run your own flow, called only when the permission was never asked:
options.permissions = .custom { await askInMyOwnWay() }   // returns MicrophoneState.Permission

setup mistakes are caught before the request. the app needs NSMicrophoneUsageDescription in its info.plist, and, if sandboxed, the com.apple.security.device.audio-input entitlement. a missing one throws FourierError.setupMissing with the problem named, and MicrophoneState.isSetupValid is false. the input follows the system default and recovers when a microphone is plugged in, removed or changed.

replaceable parts

each default is a protocol or a plain value, so an app can replace one part and keep the rest. custom parts run off the main thread and never on the realtime audio thread. a custom part can change what the model hears, so it leaves the exactness claim.

NoiseProcessor

struct MyDenoiser: NoiseProcessor {
    mutating func process(_ samples: [Float]) -> [Float] {
        samples   // 16 khz mono in, the same count out
    }
}

var options = FourierOptions()
options.noise = .custom(MyDenoiser())

SpeechDetecting

one copy per session, fed off the main thread. positions count samples from the start of the session. configure(pauseToEndPhrase:) has a default that does nothing.

struct LoudnessDetector: SpeechDetecting {
    private var position = 0
    private var speaking = false

    mutating func feed(_ samples: [Float]) -> [SpeechBoundary] {
        defer { position += samples.count }
        let peak = samples.reduce(0) { max($0, abs($1)) }
        if peak > 0.02, !speaking {
            speaking = true
            return [.started(at: position)]
        }
        if peak < 0.005, speaking {
            speaking = false
            return [.ended(at: position + samples.count)]
        }
        return []
    }

    mutating func flush() -> SpeechBoundary? {
        guard speaking else { return nil }
        speaking = false
        return .ended(at: position)
    }
}

var options = FourierOptions()
options.speechDetector = LoudnessDetector()

ModelStore

the default HuggingFaceModelStore downloads the pinned checkpoint with resume, checks its sha256 and remembers a verified file. a custom store returns a folder that holds the files named in request.files. cancellation must keep partial files.

struct LocalStore: ModelStore {
    var folder: URL

    func prepare(_ request: ModelRequest,
                 progress: @escaping @Sendable (ModelStoreProgress) -> Void) async throws -> URL {
        progress(ModelStoreProgress(stage: .check, fraction: 1))
        return folder
    }
}

errors

everything the sdk throws is a FourierError, and each case names the real cause. FourierError is LocalizedError and CustomStringConvertible, and its description says what to do, in lowercase and ready to show.

do {
    let live = try await speech.listen()
    _ = try await live.finish()
} catch let error as FourierError {
    switch error {
    case .microphoneDenied:
        speech.openMicrophoneSettings()
    case .cancelled:
        break
    default:
        print(error.description)
    }
}

the default ui

every view is built only on the public api and takes custom content and styling.

FourierKitUI is an optional second import, import FourierKitUI. the core sdk never depends on swiftui. the module ships the allo variable font, unchanged and with its license, and registers it for the app process on first use, so apps need no font setup. every view is built only on the public api above. the models are on the main actor and only draw. the work stays off it.

    }
}

exactness and what it covers

on the three golden clips, the default path gives the same token ids and the same final text as hugging face transformers running the original weights. the reference is pinned to one transformers commit, runs on the cpu in 32-bit float with a batch of one, and is frozen in golden/.

caseclaim
audio up to 120 s, default optionsone pass. identical to the reference on the three golden clips. the golden test checks this on the engine and again through transcribe for a file and a recording.
audio over 120 scut at quiet points and joined. that changes the model's input, so it is not claimed identical to one reference pass.
a piece that hits the token limitsplit and decoded again, and counted in tokenLimitSplits. reachedStop is false if it could not be split further.
any batch width, slot or loadscores are bit-identical to a run alone. the golden test checks batches and slot refill.
changed decoding optionsgreedy, a different beam count, token limit, repeat guard or context leave the exact path.
custom partscustom noise processing, speech detection or audio sources change what the model hears, so they leave the exact path.
files and recordingsnever cleaned by default, so they can match the reference. file decoding and resampling are outside the contract, because apple's and python's will not match bit for bit. the contract starts at 16 khz mono float32 samples.
listendrafts use greedy search and are not exact. the final transcript is the exact pass over each phrase. that it equals transcribe with the same split points is a goal. the golden test does not check it yet.

the golden test is the only automated check. what it checks and how to run it is in CONTRIBUTING.md, and the numbers are on the performance page. only exact paths can be defaults: if a fast path cannot reproduce the reference, a slower exact path stays.
